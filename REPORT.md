**Спецификация варианта №10**:
* **Целевая функция**: Вычисление угла $\theta = \text{atan2}(y, x) \in [-\pi, +\pi]$ методом CORDIC в векторном режиме (Vectoring mode).

* **Тип архитектуры**: Комбинационная логика (отсутствие внутренних тактовых сигналов, триггеров и конвейерных регистров; вычисление выполняется за один проход через развернутую логическую цепочку).

## 4. Выполнение задания

### 4.1. Описание целевого алгоритма и функциональной модели
Метод CORDIC (COordinate Rotation DIgital Computer, Jack E. Volder, 1959) позволяет вычислять тригонометрические, гиперболические и трансцендентные функции с помощью исключительно сдвигов и сложений/вычитаний.

Для нахождения функции $\text{atan2}(y, x)$ алгоритм используется в **векторном режиме** (Vectoring mode). Вектор $(x, y)$ последовательно поворачивается в сторону оси абсцисс до тех пор, пока координата $y$ не приблизится к нулю ($y \to 0$). Накопленная сумма углов элементарных поворотов дает искомый угол $\theta$.

#### Математический базис:
1. **Приведение к правой полуплоскости**:
   Поскольку базовый алгоритм CORDIC сходится только в диапазоне углов $[-\pi/2, +\pi/2]$, вектор из левой полуплоскости ($x < 0$) зеркально отражается относительно начала координат с начальным сдвигом угла на $\pi$:
   $$\text{если } x < 0: \quad x_0 = -x, \quad y_0 = -y, \quad \theta_0 = \pi$$
   $$\text{иначе: } \quad x_0 = x, \quad y_0 = y, \quad \theta_0 = 0$$

2. **Итерации поворота (32 каскада, $i = 0, 1, \dots, 31$)**:
   На каждом шаге знак вращения $d_i \in \{-1, +1\}$ выбирается так, чтобы уменьшить координату $y$:
   $$d_i = \begin{cases} -1, & \text{если } y_i > 0 \\ +1, & \text{если } y_i \le 0 \end{cases}$$
   Формулы пересчета координат и угла:
   $$x_{i+1} = x_i - d_i \cdot (y_i \cdot 2^{-i})$$
   $$y_{i+1} = y_i + d_i \cdot (x_i \cdot 2^{-i})$$
   $$\theta_{i+1} = \theta_i - d_i \cdot \alpha_i$$
   где $\alpha_i = \arctan(2^{-i})$ — предрассчитанные константы таблицы `ATAN_TABLE`.

3. **Нормализация угла**:
   В конце вычислений результирующий угол нормализуется к основному диапазону $[-\pi, +\pi]$:
   $$\text{если } \theta > \pi: \theta = \theta - 2\pi; \quad \text{если } \theta < -\pi: \theta = \theta + 2\pi$$

1. **`atan2_cordic_comb` (Design Under Test / Accelerator)**:
   * Чисто комбинационный модуль без памяти и тактирования (`always_comb`).
   * Внутри модуля цикл из 32 итераций разворачивается компилятором в глубокую каскадную сеть комбинационных сумматоров и арифметических сдвигателей `>>>`.
   * Время вычисления определяется исключительно физической задержкой распространения сигнала в кремнии.
2. **`NEXYS4_DDR` (Top-level Wrapper)**:
   * Модуль верхнего уровня проекта. Содержит тактовый генератор `sys_clk` (100 МГц), синхронизатор сброса `reset_sync`, шинный мастер `udm` и контрольно-статусные регистры CSR.
3. **`udm` (UART-based Debug Module)**:
   * Аппаратный модуль связи, преобразующий последовательные пакеты UART в транзакции параллельной 32-битной шины `MemSplit32`.
4. **`testmem` (`ram_dual`)**:
   * Блок двухпортовой блочной памяти объемом 4 КБ для начального самотестирования шины UDM.

### 4.3. Форматы данных и адресная карта CSR
Поскольку отношение $\frac{y}{x}$ не изменяется при масштабировании, аргументы в формате фиксированной точки Q16.16 передаются в 32-битные регистры без масштабирования как знаковые целые числа в дополнительном коде (`signed [31:0]`).

Выходной угол возвращается в формате **Q3.29**:
* Бит 31: знак числа;
* Биты [30:29]: целая часть (числа от $-4$ до $+3$);
* Биты [28:0]: 29 дробных бит (масштаб $1.0 = 2^{29} = 536\,870\,912$).
* Константа $\pi \approx 3.14159265 \implies 3.14159265 \times 2^{29} \approx 1\,686\,629\,713 = \text{0x6487ed51}$.

#### Адресная карта системной шины:
| Адрес (Hex) | Имя регистра / блока | Направление | Назначение |
| :--- | :--- | :---: | :--- |
| `0x00000000` | `CSR_LED` | Запись/Чтение | Управление 16-ю светодиодами платы |
| `0x00000004` | `CSR_SW` | Чтение | Чтение состояния 16-ти переключателей |
| **`0x10000000`** | **`CSR_Y_ADDR`** | **Запись** | **Входной аргумент $y$ ускорителя (32 бит, signed)** |
| **`0x10000004`** | **`CSR_X_ADDR`** | **Запись** | **Входной аргумент $x$ ускорителя (32 бит, signed)** |
| **`0x20000000`** | **`CSR_ANGLE_ADDR`**| **Чтение** | **Вычисленный угол $\theta = \text{atan2}(y, x)$ (Q3.29)** |
| `0x80000000`–`0x80000FFC` | `TESTMEM` | Запись/Чтение | Базовый блок памяти BRAM (4 КБ) |

2. **Квадрант II** ($y = +100, x = -100$): ожидаемый результат `0x4b60916b` ($\approx +2.3555\text{ рад} \approx +3\pi/4$).

5. **Положительная полуось $+Y$** ($y = +100, x = 0$): ожидаемый результат `0x324a5b8e` ($\approx +1.5716\text{ рад} \approx +\pi/2$).
6. **Начало координат** ($y = 0, x = 0$): результат `0x00000000` ($0.0\text{ рад}$).

Симуляция подтвердила корректную реакцию модуля: на временных диаграммах при чтении адреса `0x20000000` возвращаются расчетные значения.

2. На каждой точке данные с ПЛИС побитово сверялись с функцией `atan2_cordic_hw(y, x)` из эталонного файла [`10-atan2_cordic.py`](sw/10-atan2_cordic.py).
3. **Результат валидации**:

### 4.5. Характеристики разработанной аппаратуры

#### 1. Временные параметры (Timing):
* **Целевая тактовая частота**: $F_{clk} = 100\text{ МГц}$ (период $T = 10.0\text{ нс}$).
* **Worst Negative Slack (WNS)**: **$-121\text{ нс}$** (Setup Timing Violation).
* **Total Negative Slack (TNS)**: **$-3888\text{ нс}$**.
* **Число нарушенных конечных точек (Failing Endpoints)**: **32** (ровно 32 бита регистра шины чтения `udm_csr_rdata[31:0]`).
* **Worst Hold Slack (WHS)**: **$+0.068\text{ нс}$** (Hold Timing удовлетворен).
* **Worst Pulse Width Slack (WPWS)**: **$3.0\text{ нс}$**.

> **Физический анализ нарушения WNS:**  
> В комбинационной схеме отсутствует разбиение на такты: сигнал проходит сквозь все 32 каскада CORDIC подряд. Задержка распространения ($t_{pd}$) через эту цепочку на кристалле Artix-7 составляет около **$131\text{ нс}$**. При попытке синхронно защелкнуть результат за 1 такт ($10\text{ нс}$) возникает запас по времени:
> $$\text{Slack} = T_{\text{req}} - t_{pd} = 10\text{ нс} - 131\text{ нс} = \mathbf{-121\text{ нс}}$$
> Это фундаментальное свойство чисто комбинационных вычислителей глубоких функций, что служит мотивацией для перехода к многотактовой и конвейерной архитектурам. При этом на практике плата функционирует полностью безошибочно, так как команды чтения с хост-ПК приходят через медленный UART (интервал между транзакциями составляет более $10\,000\text{ нс} \gg 131\text{ нс}$), и сигнал на входах выходного регистра успевает гарантированно установиться.

#### 2. Производительность:
* **Задержка вычисления (Latency)**:
  * Внутренняя задержка комбинационного вычислителя: **0 тактов** (асинхронная задержка $\approx 131\text{ нс}$).
  * Системная задержка в составе шины UDM: 1 такт на фиксацию операндов в CSR + 1 такт на чтение результата по шине.
* **Интервал инициации (Initiation Interval, II)**:
  * Теоретический аппаратный: **1 такт** ($10\text{ нс}$).
* **Пропускная способность (Throughput)**:
  * Теоретическая пропускная способность комбинационного ядра: **$1\text{ оп/такт} = 100\text{ Моп/с}$** (при условии обеспечения требуемого времени установки).
  * Реальная пропускная способность в составе UDM-системы: ограничена скоростью интерфейса UART ($921600\text{ бод} \implies \approx 25\,000\text{ транзакций/с}$).
